# HAECHI Component Checklist

HAECHI 화면을 새로 만들거나 수정할 때 사용하는 공통 체크리스트입니다.

## 1. 공통 체크

- [ ] 화면이 `Top Bar + Left Rail + Main Workspace` 구조를 따르는가
- [ ] 메인 작업 영역이 가장 넓고 가장 어두운가
- [ ] 패널 간 간격이 `16px` 기준으로 정리되어 있는가
- [ ] 라운드 값이 시스템 기준 안에서만 사용되는가
- [ ] 강조색이 블루 하나로 통제되고 있는가
- [ ] 상태색이 의미 전달 용도로만 쓰이고 있는가
- [ ] 한 화면에 가장 중요한 CTA가 1개만 존재하는가
- [ ] 모바일에서 세로 적층 시 정보 우선순위가 유지되는가

## 2. Top Bar

- [ ] 높이가 `48~56px` 범위 안에 있는가
- [ ] 좌측에는 브랜드와 1차 메뉴만 있는가
- [ ] 우측에는 검색, 알림, 세션 정보만 정리되어 있는가
- [ ] 활성 메뉴가 `텍스트 강조 + 하단 블루 라인`으로 표현되는가
- [ ] 탑바가 본문보다 한 톤 더 어두운가

## 3. Left Rail

- [ ] 폭이 `56~64px` 범위 안에 있는가
- [ ] 아이콘 스타일이 일관적인가
- [ ] 기본, hover, active 색 규칙이 지켜지는가
- [ ] active 상태가 `블루 틴트 + 강조 아이콘`으로 표현되는가
- [ ] 한 레일 안에 과도한 색 사용이 없는가

## 4. Panel

- [ ] 패널 배경이 시스템 다크 톤을 따르는가
- [ ] 보더가 `1px` 얇은 선으로 정리되어 있는가
- [ ] 대형 패널과 일반 패널의 라운드가 통일되어 있는가
- [ ] 제목, 설명, 액션의 시각적 계층이 분명한가
- [ ] 패널 안에 또 다른 패널이 들어갈 때 한 단계만 밝아지는가

## 5. Typography

- [ ] 페이지 타이틀, 섹션 타이틀, 본문, 메타 라벨의 크기 계층이 분명한가
- [ ] 설명 텍스트가 제목보다 과하게 두껍지 않은가
- [ ] 메타 라벨은 짧고 반복 가능하게 설계되었는가
- [ ] 숫자 정보가 본문보다 약간 더 강조되는가

## 6. Button

- [ ] Primary 버튼이 화면당 1개 기준으로 유지되는가
- [ ] Secondary 버튼이 다크 배경 + 얇은 보더 규칙을 따르는가
- [ ] Danger 버튼이 삭제/위험 액션에만 쓰이는가
- [ ] Ghost 버튼이 배경 없이 보조 액션으로 쓰이는가
- [ ] 버튼 높이가 `40px` 또는 `48~52px` 기준 안에 있는가

## 7. Input / Select / Form

- [ ] 입력창 높이가 `40~44px` 범위 안에 있는가
- [ ] 라벨이 입력창 위에 있는가
- [ ] placeholder와 실제 값의 색 대비가 구분되는가
- [ ] 포커스 상태가 `블루 보더 + 약한 외곽광`으로 통일되는가
- [ ] 오류 상태가 배경이 아니라 보더 중심으로 표현되는가

## 8. Card

- [ ] 카드 구조가 `식별자 + 정보 + 상태/수치` 흐름을 따르는가
- [ ] 선택 상태가 보더 변화로 먼저 인식되는가
- [ ] hover 애니메이션이 과하지 않은가
- [ ] 텍스트 계층이 3단 이내로 정리되는가
- [ ] 카드 간 높이와 여백이 일정한가

## 9. Status / Badge / Pill

- [ ] 정상, 주의, 위험, 비활성 상태가 명확히 구분되는가
- [ ] 상태 배지가 강한 채움보다 옅은 tint 중심인가
- [ ] 같은 상태가 화면마다 다른 색으로 표현되지 않는가
- [ ] 상태 pill 크기와 라운드가 일관적인가

## 10. Summary Tile

- [ ] 구조가 `라벨 → 큰 수치 → 보조 설명` 순서인가
- [ ] 수치가 가장 먼저 읽히는가
- [ ] 카드 배경이 과하게 눈에 띄지 않는가
- [ ] 작은 화면에서 1열 또는 2열로 안정적으로 줄어드는가

## 11. Table / List

- [ ] 행 구분이 줄무늬보다 보더 중심으로 설계되었는가
- [ ] hover 시 시각 변화가 과하지 않은가
- [ ] 선택 행이 블루 바 또는 보더 강조로 보이는가
- [ ] 헤더와 본문의 정렬 규칙이 일정한가

## 12. Canvas / Map

- [ ] 메인 캔버스가 가장 어두운 레이어로 유지되는가
- [ ] 메타 정보가 화면 구석에 얇게 정리되는가
- [ ] 캔버스 위 포인트 색이 제한적으로만 쓰이는가
- [ ] 작업 오버레이가 패널 UI와 충돌하지 않는가

## 13. Empty / Loading / Error

- [ ] Empty 상태에 설명과 다음 액션이 포함되는가
- [ ] Loading 상태가 문맥 안에서 자연스럽게 표현되는가
- [ ] Error 상태가 붉은 보더/텍스트 중심으로 표현되는가
- [ ] 시스템 화면에서 과한 모션이 없는가

## 14. 로그인 화면 전용

- [ ] 좌측 설명 / 우측 인증 구조가 유지되는가
- [ ] 선택된 권한과 계정이 명확하게 드러나는가
- [ ] 로그인 CTA보다 현재 선택 프로필이 더 먼저 읽히는가
- [ ] 보안 게이트처럼 신뢰감 있는 톤을 유지하는가

## 15. 대시보드 전용

- [ ] 핵심 상태와 요약 정보가 상단에서 빠르게 읽히는가
- [ ] 중앙 작업 영역이 가장 중요하게 보이는가
- [ ] root와 personal의 정보 범위가 분명히 나뉘는가
- [ ] 개인 계정 화면에서 권한 범위가 분명히 안내되는가
- [ ] 전체 화면이 복잡해 보여도 정보 우선순위는 유지되는가
