# HAECHI Design System

HAECHI의 로그인 화면과 운영 대시보드를 기준으로 정리한 UI 디자인 규칙 문서입니다.

## 1. 디자인 방향

- 핵심 키워드: `보안 게이트`, `실시간 관제`, `정확한 구조`, `차분한 긴장감`
- 전체 인상은 화려함보다 `운영자가 1초 안에 읽을 수 있는 구조감`을 우선합니다.
- 로그인 화면은 `신뢰감 있는 인증 진입점`, 대시보드는 `밀도 높은 운용 캔버스`로 해석합니다.
- 두 화면 모두 같은 시각 언어를 사용합니다.
  - 어두운 배경
  - 얇은 보더
  - 블루 포커스
  - 절제된 상태 색

## 2. 레이아웃 원칙

### 2.1 전역 구조

- 기본 구조는 `Top Bar + Left Rail + Main Workspace`
- 관제형 페이지는 `설정 패널 + 작업 캔버스 + 보조 패널`의 3영역 구성을 기본으로 합니다.
- 로그인 화면은 예외적으로 `좌측 설명 40% / 우측 인증 60%`의 2단 분할을 사용합니다.

### 2.2 간격 규칙

- 화면 기본 바깥 여백: `20~36px`
- 패널 간 간격: `16px`
- 패널 내부 여백: `18~24px`
- 카드 내부 여백: `14~18px`
- 정보 그룹 간 수직 간격: `12~18px`

### 2.3 영역 우선순위

- 시선 흐름은 항상 아래 순서를 따릅니다.
  1. 페이지 제목
  2. 현재 상태 또는 현재 작업
  3. 핵심 수치 / 선택 상태
  4. 보조 설명 / 로그 / 메타 정보
- 중앙 작업 영역은 가장 넓고 가장 어둡게 유지합니다.
- 설정 패널은 중앙보다 한 톤 밝게 두어 레이어를 분리합니다.

### 2.4 반응형 기준

- Desktop: `3단 레이아웃 유지`
- Tablet: `좌측/우측 패널을 위아래로 적층`
- Mobile: `메인 정보 우선`, 사이드 패널은 접기 또는 세로 순차 배치

## 3. 색상 시스템

### 3.1 핵심 원칙

- 완전한 검정보다 `블루가 섞인 차콜 계열`을 사용합니다.
- 색은 배경을 칠하는 용도보다 `상태와 포커스 전달`에 사용합니다.
- 메인 액센트는 블루 하나만 유지합니다.
- 상태 색은 의미 전달 용도로만 제한적으로 사용합니다.

### 3.2 기본 토큰

```css
:root {
  --bg-app: #111214;
  --bg-surface: #171a20;
  --bg-panel: #1d2128;
  --bg-panel-strong: #242932;

  --line-soft: rgba(255, 255, 255, 0.06);
  --line-default: rgba(255, 255, 255, 0.08);
  --line-strong: rgba(77, 141, 255, 0.38);

  --text-primary: #f5f7fb;
  --text-secondary: #9aa4b2;
  --text-tertiary: #7f8a98;

  --accent: #4d8dff;
  --accent-soft: #9abfff;

  --state-success: #48d597;
  --state-warning: #ffc65c;
  --state-danger: #ff6b6b;
  --state-muted: #747f90;
}
```

### 3.3 색상 사용 규칙

- 블루는 아래 요소에 우선 적용합니다.
  - 선택 상태
  - 포커스 상태
  - 활성 탭
  - 주요 CTA
- 초록은 `정상`, 노랑은 `주의`, 빨강은 `위험/삭제`, 회색은 `비활성/오프라인`에만 사용합니다.
- 강한 채도의 색면은 큰 영역에 사용하지 않습니다.
- 항상 `어두운 바탕 + 옅은 틴트 + 얇은 보더` 조합을 우선합니다.

## 4. 표면과 패널 규칙

### 4.1 Panel

- 기본 패널 배경: `--bg-panel`
- 패널 보더: `1px solid --line-soft`
- 대형 패널 라운드: `20~22px`
- 일반 패널 라운드: `16~18px`
- 그림자: `0 16px 40px rgba(0, 0, 0, 0.28)` 수준으로 절제합니다.

### 4.2 레이어 구분

- 레이어는 `색상 차이`보다 `명도 차이 + 보더 + 간격`으로 구분합니다.
- 중첩 패널은 최대 한 단계까지만 밝아질 수 있습니다.
- 작업 캔버스는 패널보다 더 어둡고, 보더는 더 약하게 둡니다.

## 5. 타이포그래피 규칙

- 페이지 타이틀: `28~40px`
- 섹션 타이틀: `18~22px`
- 카드 타이틀: `15~17px`
- 본문: `14~16px`
- 메타 라벨: `11~12px`

### 5.1 텍스트 계층

- `Primary`: 흰색 계열, 제목과 핵심 수치
- `Secondary`: 회청색 계열, 설명과 보조 정보
- `Tertiary`: 더 약한 회색, 메타 정보와 placeholder

### 5.2 라벨 스타일

- 보조 라벨은 대문자 또는 짧은 한글 라벨로 통일합니다.
- 자간을 넓게 주어 계기판 같은 느낌을 유지합니다.
- 라벨은 강조보다 구분 역할을 수행해야 합니다.

## 6. 컴포넌트 규칙

### 6.1 Top Bar

- 높이: `48~56px`
- 좌측: 브랜드, 1차 내비게이션
- 우측: 검색, 알림, 언어, 세션 정보
- 활성 메뉴는 `텍스트 강조 + 하단 블루 라인`으로 표시합니다.
- 탑바는 본문보다 반 톤 더 어둡게 유지합니다.

### 6.2 Left Rail

- 폭: `56~64px`
- 아이콘 중심 구조로 유지합니다.
- 기본 아이콘 색: `--text-tertiary`
- hover: `--text-primary`
- active: `--accent`
- active 상태는 `배경 채우기`보다 `블루 틴트 사각형`을 우선합니다.

### 6.3 Tabs

- 페이지 탭과 패널 탭을 구분합니다.
- 페이지 탭은 `텍스트 중심 + 하단 라인`
- 패널 탭은 `세그먼트 버튼` 구조
- 활성 탭은 진한 채움 대신 `보더 + 옅은 틴트`를 사용합니다.

### 6.4 Buttons

- `Primary`
  - 배경: `--accent`
  - 텍스트: `--text-primary`
  - 가장 중요한 액션 1개만 사용
- `Secondary`
  - 다크 배경
  - 얇은 보더
  - hover 시 블루 틴트
- `Danger`
  - 빨간 보더 또는 빨간 텍스트
  - 긴급/삭제 액션에만 사용
- `Ghost`
  - 배경 없음
  - hover 시 약한 surface 노출

기본 높이 규칙:

- 일반 버튼: `40px`
- 강조 버튼: `48~52px`

### 6.5 Inputs / Select / Form

- 입력창 높이: `40~44px`
- 배경은 패널보다 약간 더 어둡게 둡니다.
- 포커스 상태는 `블루 보더 + 약한 외곽광`
- 라벨은 항상 입력창 위에 둡니다.
- 오류 상태는 빨간 배경이 아니라 `빨간 보더`로 표현합니다.

### 6.6 Cards

- 공통 구조는 `좌측 식별자 + 중앙 정보 + 우측 상태/수치`
- hover는 `translateY(-1px)` 수준으로 최소화합니다.
- 선택 상태는 `보더 변화`가 먼저 보이게 합니다.
- 카드 안 텍스트는 최대 3단 계층만 유지합니다.
  - 이름
  - 보조 정보
  - 상태 또는 수치

### 6.7 Status Pill

- 모든 상태는 pill 형태로 통일합니다.
- 색상 규칙:
  - 정상: success tint
  - 주의: warning tint
  - 오류/위험: danger tint
  - 비활성: muted tint
- pill은 채도가 높지 않아야 하며, 배경은 항상 반투명 tint를 사용합니다.

### 6.8 Summary Tile

- 구조: `라벨 → 큰 수치 → 짧은 설명`
- 핵심은 숫자 강조이고, 배경은 조용해야 합니다.
- 한 줄 최대 4개 배치
- 작은 화면에서는 1열 또는 2열로 줄입니다.

### 6.9 Table / List

- 줄무늬보다 `행 보더` 중심으로 구분합니다.
- 행 높이: `40~44px`
- hover 시 배경을 크게 밝히지 않습니다.
- 선택 행은 `좌측 블루 바` 또는 `전체 보더 강조`로 처리합니다.

### 6.10 Canvas / Map Area

- 메인 작업 캔버스는 화면에서 가장 어두운 레이어입니다.
- 주변 패널보다 시각적으로 조용해야 합니다.
- 좌표, 해상도, origin 등의 메타 정보는 화면 구석에 얇게 배치합니다.
- 캔버스 내부 강조 색은 블루, 그린, 옐로 정도로 제한합니다.

### 6.11 Empty / Loading / Error

- Empty
  - 약한 아이콘
  - 한 줄 설명
  - 보조 액션 1개
- Loading
  - 중앙 거대 스피너보다 `문맥 안 로딩 메시지` 우선
- Error
  - 빨간 텍스트 + 빨간 보더
  - 과한 경고 배경은 지양

### 6.12 Modal / Drawer

- 중요한 결정은 Modal
- 보조 편집은 Drawer
- 모달 라운드: `20px`
- destructive action은 우측 하단에 배치합니다.
- Drawer는 기존 패널과 같은 색 체계를 사용해 흐름이 끊기지 않게 합니다.

## 7. 로그인 화면 규칙

### 7.1 역할

- 로그인 화면은 `보안 게이트`처럼 보여야 합니다.
- 설명과 인증이 동시에 보여야 하며, 시스템 신뢰감을 먼저 전달합니다.

### 7.2 구조

- 좌측: 브랜드, 시스템 설명, 상태 요약
- 우측: 권한 선택, 프로필 카드, 로그인 CTA
- 좌우 비율은 `40 : 60` 또는 `45 : 55`

### 7.3 시각 규칙

- 왼쪽 영역은 정보와 신뢰감
- 오른쪽 영역은 선택과 액션 중심
- 선택된 권한 카드와 계정 카드는 같은 선택 문법을 사용합니다.
- 가장 강한 시선은 로그인 버튼이 아니라 `현재 선택된 프로필`에 갑니다.

## 8. 대시보드 규칙

### 8.1 역할

- 대시보드는 `실시간 상황 파악`이 최우선입니다.
- 미적인 장치보다 `빠른 읽기`, `명확한 상태`, `작업 위치 인지`를 우선합니다.

### 8.2 구조

- 상단: 현재 세션, 전역 상태, 로그아웃 등 전역 맥락
- 중단: 핵심 요약 카드
- 본문: 플릿 목록, 상세 패널, 계정 상태 또는 권한 패널
- 작업형 화면은 중앙 캔버스를 우선적으로 넓게 확보합니다.

### 8.3 root / personal 분기

- `root`
  - 전체 시스템 범위를 본다는 느낌을 강조
  - 전체 계정 상태 패널 포함
- `personal`
  - 접근 제한과 담당 범위를 명확히 노출
  - 내 권한, 허용 구역, 접근 가능한 로봇 수를 명확히 보여줌

## 9. 금지 규칙

- 큰 면적의 순수 블루/레드 배경 사용 금지
- 한 화면에 강조색 여러 개 혼용 금지
- 카드마다 다른 라운드값 사용 금지
- 불필요한 글로우, 과도한 네온 효과 금지
- 애니메이션 남용 금지
- 같은 의미의 버튼 스타일이 화면마다 바뀌는 것 금지

## 10. 최종 운영 원칙

- 새 컴포넌트는 아래 4개 계열 안에서만 파생합니다.
  - 패널형
  - 카드형
  - 필드형
  - 상태형
- 모든 화면은 `검은 관제실 위의 얇은 블루 인터페이스`라는 공통 정체성을 유지합니다.
- 예쁘게 보이는 것보다 `빠르고 정확하게 읽히는 것`을 우선합니다.
