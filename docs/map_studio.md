HAECHI 시스템 맵 스튜디오 및 통합 관제 뷰 구현 기획서

1. 개요 (Overview)

본 기획서는 로봇 관제 및 함대 관리 시스템 'HAECHI'의 핵심 기능인 **맵 스튜디오(Map Studio)**와 이를 활용한 **통합 관제 뷰(Main Monitoring View)**의 세부 구현 방안을 정의합니다.
로봇의 실제 SLAM 데이터(물리적 좌표계)와 사용자가 인지하는 UI 도면(시각적 좌표계)을 완벽하게 정합하고, 단일 격실부터 전체 건물 단위까지 아우르는 확장성 있는 맵 관리 체계를 구축하는 것을 목표로 합니다.

2. 맵 계층 구조 정의 (Map Hierarchy)

맵 시스템은 스케일과 용도에 따라 4가지 계층으로 분류됩니다.

계층 (Scale)

명칭

정의 및 역할

Global

Domain

전체 부지 및 건물 단위. 3D 공간상에 여러 Deck이 Z축으로 적층된 형태.

Spatial

Deck

단일 층(Floor) 평면. 로봇이 연속적으로 주행하는 2D 작업 공간.

Base

Spot

최소 작업 단위 (격실, 구역). 로봇의 단일 맵(ROS2 Map) 데이터와 1:1 매칭.

Link

Portal

Spot 간 또는 Deck 간의 이동을 연결하는 전이 구역 (계단, 엘리베이터).

3. 맵 스튜디오 세부 기능 기획 (Map Studio)

사용자(관리자)가 맵을 생성, 편집, 조립하는 저작 도구입니다. 각 스케일별로 특화된 에디터가 제공됩니다.

3.1. Spot Editor (단위 맵 정합 및 보정)

목적: 원본 로봇 맵(YAML/PGM 등)과 고해상도 UI 도면(PNG/SVG 등)의 스케일 및 원점을 동기화합니다.

UI 도면 업로드 및 기본 설정: 사용자가 예쁜 UI용 도면을 업로드.

로봇 원점(Origin) 강제 지정 [핵심]: 도면 상의 특정 픽셀을 클릭하여 ROS2 map 프레임의 기준점(0,0)으로 강제 매핑.

해상도(Resolution) 캘리브레이션: * 로봇 맵의 해상도(예: 0.05m/px)와 UI 도면의 해상도 차이를 보정.

맵 상의 두 점을 클릭하고 실제 거리(m)를 입력하여 자동 스케일링 기능 제공.

헤딩(Orientation) 보정: 로봇이 맵핑할 때 틀어진 각도를 UI 도면의 정방향에 맞게 회전 보정.

그리드 설정: 실제 물리적 크기 체감을 위한 1m 단위 그리드 오버레이 및 색상 변경.

3.2. Deck Editor (층면 조립 및 논리적 연결)

목적: 개별적으로 캘리브레이션 된 Spot들을 하나의 Deck(층)으로 조립하고 로직을 부여합니다.

Spot Drag & Drop 배치: 좌측 라이브러리 패널에서 저장된 Spot을 중앙 캔버스로 드래그하여 배치.

크기 조절 및 자동 역산 로직 [핵심]: * 사용자가 UI 상에서 Spot의 크기를 임의로 조절하거나 위치를 변경할 경우, 내부 엔진이 변경된 픽셀 비율을 계산하여 로봇의 Global Pose(원점 및 위치 데이터)를 자동 역산 및 업데이트.

Visual Snapping (시각적 스냅): 물리적으로 분리된 Spot 간의 경계선을 자석처럼 붙여 하나의 매끄러운 평면처럼 렌더링.

Portal 및 트리거 배치:

Spot과 Spot이 만나는 경계면에 Portal(수평 통로) 아이콘 배치.

로봇이 해당 구역을 지날 때 자신의 위치를 재조율할 수 있도록 ArUco 마커 위치나 API 트리거 라인 설정.

3.3. Domain Editor (3D 위상 및 수직 공간 설계)

목적: 여러 Deck을 Z축으로 쌓고, 건물 전체의 수직적 토폴로지를 구성합니다.

3D 궤도(Orbit) 뷰: Fusion 360과 유사한 마우스 컨트롤(회전, 팬, 줌)을 지원하는 3D 캔버스.

Deck 적층 (Z-Axis Stacking): 작성 완료된 Deck들을 레이어 층층이 쌓고, 층고(m) 설정.

Vertical Portal 연결: * 엘리베이터, 경사로, 계단 등을 나타내는 3D Portal 생성.

"1층(Deck 1)의 A엘리베이터 ↔ 2층(Deck 2)의 A엘리베이터" 간의 논리적 라우팅 경로 생성.

4. 통합 관제 뷰 화면 기획 (Main Monitoring View)

맵 스튜디오에서 작성된 맵을 바탕으로 실제 로봇들을 관제하는 메인 화면입니다. 맵이 화면의 최대 면적을 차지합니다.

4.1. 화면 레이아웃

Main Canvas (Center): 맵과 로봇의 실시간 위치, 주행 경로가 렌더링되는 가장 넓은 영역.

Floating Indicators (Overlays): 맵 위에 반투명하게 떠 있는 위젯들. 로봇 배터리 상태, 현재 미션 진행률, 긴급 알림 등을 표시.

Context Sidebar (Right/Left): 선택된 로봇의 상세 정보나 특정 구역(Spot)의 이벤트 로그를 보여주는 접이식 패널.

4.2. 사용자의 직관적인 맵 탐색 및 선택 UI

다양한 스케일의 맵을 사용자가 길을 잃지 않고 쉽게 선택할 수 있는 내비게이션 기능입니다.

Semantic Zoom (마우스 휠 기반 자동 전환)

줌 아웃 (최대): Domain 모드 뷰 (3D 층별 오버뷰 또는 전체 사이트 평면).

줌 인 (중간): Deck 모드로 부드럽게 전환. 해당 층의 전체 모습과 로봇들의 분포 확인.

줌 인 (최대): 특정 Spot으로 포커스. 로봇의 라이다(LiDAR) 스캔 라인, 경로 계획 선 등 세밀한 데이터 표시.

미니맵 및 계층 트리(Breadcrumb) 패널 (수동 선택)

위치: 화면 좌측 상단 또는 하단 플로팅 패널.

구조: Domain (서울 공장) > Deck (2층 생산라인) > Spot (A격실) 형태의 Breadcrumb 네비게이션 제공.

동작: * 트리 구조에서 특정 Deck이나 Spot을 클릭하면 메인 캔버스의 카메라가 해당 영역으로 자동 패닝(Panning) & 줌인.

Deck 간 빠른 이동을 위한 '층수(1F, 2F, 3F...)' 퀵 셀렉터 버튼 제공.

로봇 중심 추적(Tracking) 모드

인디케이터에서 특정 로봇을 클릭하면, 화면이 해당 로봇이 위치한 Spot으로 자동 전환되며 로봇을 화면 중앙에 고정(Tracking)하여 추적.

로봇이 Portal을 타고 층(Deck)을 이동하면, 관제 뷰의 맵도 자동으로 다음 층으로 스위칭됨.

5. 데이터 흐름 및 기술적 고려사항

Coordinate Transformer (좌표계 변환기): 프론트엔드(Tauri/React)에서 픽셀 단위로 클릭/드래그한 좌표를 ROS2의 미터(m) 단위 전역/지역 좌표계로 실시간 변환하는 유틸리티 클래스가 반드시 구현되어야 합니다.

LOD (Level of Detail) 렌더링: 고해상도 이미지를 사용하므로, Domain 뷰에서는 썸네일 급의 가벼운 이미지를 렌더링하고, Spot 뷰로 확대할 때 고해상도 타일을 로드하는 방식(예: Mapbox, Leaflet, 혹은 Canvas 렌더링 최적화)을 적용해야 성능 저하를 막을 수 있습니다.

상태 동기화: 맵이 스튜디오에서 수정 중(Draft)일 때와 실제 관제에 배포(Publish)되었을 때의 버전 관리가 필요합니다.
